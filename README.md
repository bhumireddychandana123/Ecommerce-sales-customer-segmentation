# E-Commerce Sales and Customer Segmentation Analysis Using Python

A data analytics and machine learning project that analyses online retail transactions, explores sales performance, builds customer-level RFM metrics, and segments customers using K-Means clustering. The complete implementation is contained in one Jupyter Notebook.

## Project Overview

The project uses the Online Retail transaction dataset to understand:

- Overall revenue and order performance
- Monthly revenue behaviour
- Best-performing products
- Revenue contribution by country
- Customer ordering and spending patterns
- Customer segments based on Recency, Frequency, and Monetary value

The analysis uses actual values calculated from `OnlineRetail.csv`. No results are hard-coded.

## Dataset and Dataset Link

The project uses the Online Retail dataset published on Kaggle:

[Online Retail Dataset on Kaggle](https://www.kaggle.com/datasets/carrie1/ecommerce-data)

The local dataset file is `OnlineRetail.csv`. It contains transaction-level records with fields including:

- `InvoiceNo`
- `StockCode`
- `Description`
- `Quantity`
- `InvoiceDate`
- `UnitPrice`
- `CustomerID`
- `Country`

The original file contains 541,909 rows and 8 columns. The notebook loads the local CSV from the project folder.

## Objectives

1. Load and understand the retail transaction data.
2. Identify missing values, duplicate records, and data types.
3. Clean transactions for reliable sales and customer analysis.
4. Calculate revenue, orders, customers, and unique products.
5. Analyse monthly, product-wise, country-wise, and customer-wise sales.
6. Create customer-level RFM metrics.
7. Use K-Means as the AI/ML component for customer segmentation.
8. Translate the calculated results into business insights.

## Data Cleaning and Preprocessing

The notebook performs the following steps:

- Removes duplicate rows.
- Converts `InvoiceDate` to datetime.
- Converts `Quantity`, `UnitPrice`, and `CustomerID` to suitable numeric types.
- Identifies cancelled invoices when `InvoiceNo` begins with `C`.
- Removes cancelled transactions from sales analysis.
- Removes rows with missing `CustomerID` for customer-level analysis.
- Removes rows with missing `Description` for product analysis.
- Removes invalid or non-positive sales quantities and invalid prices.
- Creates a `Revenue` column using:

  `Revenue = Quantity * UnitPrice`

The cleaned dataset contains 392,732 usable transaction rows after the notebook's cleaning rules are applied.

## RFM Analysis

RFM analysis creates one record per customer using three measures:

- **Recency:** Number of days since the customer's latest purchase.
- **Frequency:** Number of unique invoices/orders made by the customer.
- **Monetary:** Total revenue generated by the customer.

The latest `InvoiceDate` in the cleaned dataset is used as the reference date for calculating Recency. This keeps the calculation based on the observed transaction period.

Before clustering, the notebook applies `log1p` to the RFM features to reduce the effect of skewness and then uses `StandardScaler` to place the features on a comparable scale.

## K-Means Customer Segmentation

K-Means is used as the unsupervised machine learning component of the project.

The notebook:

1. Uses scaled RFM features as clustering inputs.
2. Tests candidate cluster counts with the Elbow Method.
3. Plots the inertia values for the candidate cluster counts.
4. Selects the cluster count from the observed elbow scores.
5. Trains K-Means with `random_state=42` and `n_init=10`.
6. Adds the resulting cluster label to the RFM dataframe.
7. Summarises average Recency, Frequency, Monetary value, and customer count for each cluster.

The executed elbow analysis selected **3 clusters**.

The observed cluster profiles were:

| Cluster | Customers | Average Recency | Average Frequency | Average Monetary |
|---:|---:|---:|---:|---:|
| 0 | 729 | 12.93 days | 13.67 orders | £8,016.79 |
| 1 | 1,922 | 161.14 days | 1.34 orders | £352.00 |
| 2 | 1,688 | 46.19 days | 3.55 orders | £1,401.91 |

Cluster numbers are identifiers produced by K-Means. They are interpreted using the displayed RFM values rather than treated as fixed business labels. The clustering describes observed customer behaviour and does not predict future sales.
